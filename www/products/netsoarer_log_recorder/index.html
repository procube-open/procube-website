NetSoarer® Log Recorder

ログ保存・解析システム プロキシ型のシングルサインオンを実現

ABOUT NetSoarer® Log Recorderとは

多様なシステムやネットワーク機器から出力される大量のログを効率的に収集してデータベースに蓄積し、高速な検索、多角的な統計分析、
柔軟なデータ加工機能を提供することで、ログの活用を支援するログ管理ソリューションです 。

FEATURES NetSoarer® Log Recorderの特長

  • 大容量ログの効率的な保管と処理能力

    Amazon S3 および Redshift、またはオンプレミスのPostgreSQLと高速SSDを利用して、ファイアウォールログなどの大量のログを効率的に収容・蓄積できます 。例えば、2TBytesのインスタンス1台でファイアウォールのトラフィックログ90日分を蓄積した実績があります。
    ログの量に応じてインスタンスを追加することで、システム全体の収容量を増やすことが可能です。
    特にファイアウォールのトラフィックログなどでは、連続する同一送信元・宛先のログを集約して件数を圧縮し、ディスク容量を抑制します。

  • 柔軟なログ形式への対応とデータ加工

    正規表現を利用してテキストログを解析しデータベース化するため、多様なログフォーマットに柔軟に対応できます。ログフォーマットが変更された場合も、設定ファイル内の正規表現を修正することで対応可能です。
    収集したログデータに対して、以下のような編集処理が可能です。
    ・併合（merge）: 異なる種類のログレコードを、例えばセッションIDをキーにして1つのレコードに統合できます。
    ・集約（summation）: キーとなるフィールドが一致する連続したレコードを1つにまとめ、その際に個数、合計値、平均値などを新たな列として追加できます。
    ・結合（join）: 例えばIPアドレスをキーとして、ネットワーク認証ログとトラフィックログなど、二つのテーブルのレコードを結合して1つのレコードにすることができます。

    検索対象を日時で絞り込むことで、さらに高速な検索を実現します。
    Web UIを通じて、AND/OR条件を組み合わせた詳細な絞り込み検索（クエリエディタ）が可能です。
    検索結果はCSVファイルとしてダウンロードでき、長時間かかる検索はバックグラウンドで実行して後からCSVで結果を得ることも可能です。
    ネットワーク別、時間帯別など様々な角度からログ件数を集計・表示する統計情報機能があり、集計済みのセルから詳細なログ一覧へドリルスルーすることもできます。

  • 検知機能による
    自動化とアラート

    バッチ処理でSQLを実行し、その問い合わせ結果の件数に応じて、指定したコマンドの起動やメール送信といったアクションを自動的に実行できます。
    例えば、特定の拒否ログが大量に発生した場合に管理者に警告メールを送信したり、1日の通信量が極端に多いパターンを検出して通知したりすることが可能です。
    アクションは、SQLの結果レコード1件ごとに実行するモードと、全レコードを対象に1回だけ実行する集約モードをサポートしています。

  • 日別・部門別の
    ログの統計分析レポート

    構造化ログやRADIUSログをOLAP解析し、日別・部門別などの月次レポートを出力できます。

FAQ よくある質問

どのような形式のログに対応していますか？

Syslog形式のメッセージに対応しており、RADIUSのアカウンティングログにも対応しています。構文解析により、ユーザ名やファイル名などの情報を自動的に抽出・構造化します。

異常が検知された場合、リアルタイムで通知されますか？

はい。問題を検知した際にはインシデントログを出力し、管理者にメール通知する機能があります。迅速な対応が可能になります。

ログの検索や分析は非技術者でも可能ですか？

はい。Webブラウザからの直感的なインターフェースで、専門知識がなくてもログの検索・閲覧・簡易分析が行えます。
また、データベースとしてAmazon Redshiftの他に、PostgreSQLと高速SSDを使用したオンプレミス環境での構築も可能です。
システム構成としては、ログ収集サーバ、Amazon S3、Amazon Redshift、そしてWeb UIを提供するサーバなどが連携して動作します 。

System Requirements 動作確認

サーバ仕様 CPU：4コア以上
ディスク容量：200GB以上を推奨
メモリ容量：16GB以上を推奨
OS：Almalinux8,9 / RedHat 8,9
ネットワーク要件 ・ユーザーが利用するクライアントとLogRecorderサーバ間でHTTP（ポート80） および HTTPS （ポート443）で通信可能であること。
・保守用端末とLogRecorderサーバ間でSSH（ポート22）で通信可能であること。
・LogRecorderサーバからインターネット経由でRedshift（ポート5439）へ接続可能であること。
・NTPサーバへ接続できること（必須ではありません）。
・SMTPリレーサーバへ接続できること（メール発信機能を利用する場合に必要）。
